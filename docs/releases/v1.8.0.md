# v1.8.0

Minor release. Updates get guard rails, and the run gets flags.

## Update guard rails

- A pacman hook warns when packages were upgraded without replaying stages — a
  bare `pacman -Syu` does the package half and leaves services, `/etc` and the
  stow tree behind. `Upgrade` only; installing a package by hand is not drift.
- `install.sh` drops `/run/hashiru-replay` for the length of a run, so a replay
  does not trip its own hook once per manifest.
- A disk-space pre-flight before the stage loop: hard error under 2 GiB, warning
  under 5 GiB. A half-applied transaction is what replay cannot repair.
- `hashiru doctor` reports whether the hook is installed and matches the repo.

## Flags

- Accepted by `hashiru update` and `hashiru install` both.
- `--no-confirm` answers every prompt yes. The reboot is the only prompt left,
  so on a full run this reboots.
- `--no-reboot` never reboots and never asks; tested first, so it wins over
  `--no-confirm`.
- `--no-reflector` skips stage 10's mirror ranking, about a minute on an update.
  `reflector.timer` stays enabled; `HASHIRU_NO_REFLECTOR=1` makes it permanent.
- `update-system` now wraps `hashiru update` instead of its own `yay -Syu`, so
  the keybind and the CLI agree on what an update is.

## Commands

- `calcurse-sync` pulls Google Calendar into calcurse, one-way on purpose.
- `msync` can ignore directories; `gd` alias added.

## Upgrading

`hashiru update`. The pacman hook is installed by stage 10, so `hashiru update
45` will not place it — a full update will, and `hashiru doctor` says whether it
arrived.
