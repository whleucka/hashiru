# v1.19.0

Xbox controllers stay paired over Bluetooth, and a crashed lock screen no
longer needs a tty.

## Game controllers

- Stage 10 sets three BlueZ options in `/etc/bluetooth/main.conf` and
  `input.conf`: `ClassicBondedOnly=false`, `JustWorksRepairing=always`,
  `FastConnectable=true`. Xbox controllers often pair without a stored key,
  and BlueZ then refused their reconnect, so every power-on meant pairing
  again. BlueZ reads no drop-ins, so only these keys are set; the rest of each
  file stays pacman's.
- xpadneo (AUR, `xpadneo-dkms`) drives Xbox One/Series pads over Bluetooth:
  correct mappings, trigger rumble, battery level. It is a DKMS module, so it
  rebuilds on every kernel upgrade.
- Pair with `bluetoothctl` (`pair`, `trust`, `connect`) and check
  `bluetoothctl info <MAC>` shows `Bonded: yes`. blueman can connect a pad
  without bonding it, which works until the pad is switched off.

## Lock screen

- If hyprlock dies (undocking during suspend did it), CTRL+ALT+L on the
  "lockscreen app died" screen starts a new one into the same lock
  (`misc.allow_session_lock_restore`). Before, the only way out was a tty.

## Binds

- SUPER+ALT+A opens Google as a chromium app, in place of Amazon.
- SUPER+SHIFT+A (Claude Code) spells its modifier `SHIFT` like every other
  bind.

## Upgrading

`hashiru update`. Stage 10 restarts bluetooth if its config changed, which
drops connected devices for a moment. Stage 20 builds xpadneo. A pad that keeps
forgetting the machine needs pairing once more with `trust`; log out and back in
for the lock-screen change.
