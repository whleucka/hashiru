# v1.7.2

Patch release. Installs get quiet, and stop compiling things nobody asked for.

## Quiet installs

- `HASHIRU_QUIET` keeps child output — pacman, makepkg, git — in the install log
  behind one progress line: stage counter, bar, percentage, clock, stage label.
- Defaults to whatever `HASHIRU_UNATTENDED` is: on for the ISO's first boot, off
  for manual runs, where that output is what you debug against. Override in
  `hashiru.conf`.
- Only draws on a real terminal — a pipe, redirect or CI degrades to plain line
  output. Warnings and errors still print as they happen, and a failed stage
  dumps the last 40 log lines.
- First boot writes to `/dev/tty1` directly, so the journal no longer fills with
  carriage returns. Serial and headless boots get plain log lines.

## Commands

- `hashiru log [-f]` pages the install log; `hashiru report` prints the warnings
  digest, including the archived copy login moves it to; `hashiru changelog
  [tag]` reads `docs/releases/`, newest first.
- `/etc/hashiru-release` gains `HASHIRU_VERSION` from `git describe --tags`;
  `status` and `doctor` lead with it, and `update` restamps it.

## Install time

- AUR packages install in one batched `yay` call, falling back to the serial loop
  on failure; failure isolation is unchanged. In a VM the bootstrap reached stage
  4 of 9 in the time it used to spend compiling at stage 3.
- `sherlock-confetti` and `sqls` leave `aur.txt` — the two compiles on the
  critical path. Neither removal uninstalls anything.

## Fixes

- `update-system` guards `paplay` and `confetti` with `command -v`.
- `iso/build.sh` warns when the ref it is pinning exists on no remote branch; the
  pin resolves on the target machine, which clones from GitHub.
- `iso/test-qemu.sh` names `qemu-desktop`; `-display gtk` needs its UI module.

## Upgrading

`hashiru update`. Quiet mode, the commands and the version stamp land on replay;
the first-boot changes and the `aur.txt` removals affect new installs only.
Reasoning: [`docs/roadmap.md`](../roadmap.md).
