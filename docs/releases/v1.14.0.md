# v1.14.0

Recovery release. Every way the install can fail now ends on a screen that
says what broke, where the log is, and what to do next, and most of them
offer a way on without starting over. Also: hashiru-tui, the system menu,
and battery charge thresholds.

## ISO

- No network: a menu with Retry, Set up WiFi (a network list and a
  passphrase prompt, instead of typing `iwctl` commands), Shell and Power
  off. A wrong passphrase asks again.
- archinstall failing shows its log and offers Retry with the same answers,
  Edit answers, Shell or Power off. A retry first cleans up the mounts and
  encrypted disk the failed run left open.
- When only the final clone and setup of Hashiru fail, Retry wiring finishes
  them without reinstalling the base system, including the `/etc/fstab`
  archinstall would have written last.
- Any other unexpected error shows where it stopped instead of quitting
  silently. Ctrl-C stops cleanly.
- The installer keeps a log at `/var/log/hashiru-stage0.log`, with no
  passwords in it.
- If the WiFi network can't be saved into the installed system, the last
  screen says so and points at `nmtui`.

## First boot

- A failed stage leaves a failure screen and a plain login prompt on tty1,
  rather than logging in automatically and starting Hyprland over it.
- The next boot resumes from the stage that failed. After three failed
  attempts it stops retrying.
- Every login shows the failure and the command to finish it, and tty1
  doesn't start Hyprland, until a run completes.

## install.sh

- A failed stage ends on the same `!!` block as the installer, with the
  resume command. Exit codes and flags are unchanged.

## Battery and idle

- New `hashiru charge 75 80`: battery charge thresholds, kept across
  updates. `off` goes back to charging to full; bare shows the setting and
  what the battery reports. Saved as `HASHIRU_CHARGE_START`/`STOP` in
  `hashiru.conf` and written to `/etc/tlp.d/50-hashiru-charge.conf`. Unset,
  which is the default, Hashiru doesn't touch thresholds. `doctor` checks
  the battery matches.
- Idle timeouts can differ per machine:
  `~/.config/hashiru/hypr/hypridle-{ac,battery}.conf` replaces Hashiru's
  file for that power source, and `~/.config/hypr/scripts/hypridle-battery
  reload` applies it without a logout. `doctor` says when hypridle isn't
  running on it yet.

## The system menu

- New: hashiru-tui, a keyboard-driven control center. `Super+Alt+Space`
  opens it floating; `hashiru tui` runs it in a terminal. Stage 99 installs
  it from a pinned tag (v0.2.0).
- Areas for updates, packages, keybinds, connectivity, wallpaper, snapshots,
  config, logs and services.
- Updates shows the release notes for what an update brings before you run
  it, and re-applies one stage (`hashiru install N`) from a picker.
- Packages sorts what Hashiru's manifests install from what you added, shows
  drift and orphans, and searches the repos and the AUR to install from.
- Services starts, stops, restarts, enables and disables system and user
  units; a failed unit in Logs goes straight to it.
- `?` shows each screen's keys. Deep links (`hashiru-tui --run
  snapshots.new`) go straight to an action, for binds and scripts.
- `hashiru status --porcelain` and `hashiru doctor --json` print stable
  machine-readable output, which the menu reads.

## Also

- Stage 60 installs herdr's Auto Title plugin, which names tabs after what
  runs in them, and herdr's Claude Code hooks and agent skill when Claude
  Code is present. `doctor` checks all three.
- Go and `gopls` in the dev tools, with `~/go/bin` on PATH.
- kitty's shader compiler (`shader-slang`) installs with kitty, so an
  install that stopped early no longer opens every terminal on a shader
  error.
- `doctor` no longer reports warnings from an earlier run that a newer one
  has replaced.

## Upgrading

`hashiru update`. The first-boot changes only apply to new installs. Charge
thresholds stay as they are until you run `hashiru charge`.
