# v1.7.1

Patch release. Three fixes, no new mechanism.

## First boot

- The bootstrap now owns tty1. A `getty@tty1` drop-in gated on
  `/etc/hashiru-firstboot.env` keeps the login prompt off the screen, so it no
  longer gets scribbled over by the bootstrap's console logging — and nobody can
  log in mid-install and collide with stage 30's autologin.
- The getty returns by itself when the bootstrap clears the env file. On the
  failure path `hashiru-firstboot.sh` restores it from its `EXIT` trap, so a
  broken run still leaves a way in.
- A failed run prints where to look (`journalctl -u hashiru-firstboot`) and how
  to resume (`./install.sh --from <stage>`).
- Banner on a cleared screen instead of kernel spam. Skipped when `/dev/tty1`
  isn't writable, so serial/headless boots are unaffected.

## Fixes

- herdr's runtime state (logs, `session.json`, `.plugins.lock`, `plugins/`) is
  gitignored. It was landing in the checkout through the stow symlink, and a
  dirty checkout is what `hashiru update` refuses to run on.
- mako: `ignore-timeout=1`, so notifications expire on `default-timeout` instead
  of whatever they ask for. Applies to `[urgency=critical]` too — those now
  clear after 10s rather than persisting.

## Upgrading

`hashiru update`. The tty1 work only affects ISO installs at first boot; the
other two land on restow.
