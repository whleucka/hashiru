# v1.7.3

Patch release. One real install-time win, and the machine can finally say which
version it is.

## Install time

- AUR packages install in one batched `yay` call, falling back to the existing
  one-at-a-time loop only when that fails. A stock `aur.txt` paid seven separate
  dependency resolutions and seven `--removemake` cycles over largely the same
  build dependencies; the common case now pays one of each.
- Nothing about failure isolation changes. A flaky build still can't abort the
  bootstrap, still lands in the warnings digest, and the stage still exits
  clean — that just isn't paid for when there is nothing to isolate.
- Downloads were already tuned (`ParallelDownloads = 10` and reflector
  mirror-ranking, both before the first `-Syu`), so this is the headroom that
  was actually left. It is minutes, not a transformation.

## Provenance

- `/etc/hashiru-release` records `HASHIRU_VERSION` from `git describe --tags`
  alongside the commit, and `hashiru status` leads with it. `v1.7.2-3-gabc1234`
  answers "which Hashiru is this" in a way twelve hex characters never did.
- `hashiru update` stamps the same field, so an update no longer drops it.
- `hashiru changelog [tag]` reads `docs/releases/`, newest first — the same
  files CI already uses for release bodies. Accepts `v1.7.2` or `1.7.2`.

## Fixes

- `update-system` guards `paplay` and `confetti` with `command -v`. Both are
  optional — `sherlock-confetti` builds from source and a failed build is
  demoted to a warning on purpose — so an update no longer ends on a
  command-not-found for the sake of an animation.

## Upgrading

`hashiru update`. The version stamp appears on the next full install or update.
