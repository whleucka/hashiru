# v1.13.0

Fingerprint release. `hashiru fingerprint on` sets up fingerprint for `sudo`
and graphical admin prompts in one command, and updates keep it set up.

## Fingerprint

- New `hashiru fingerprint on|off`. `on` checks for a reader, enrolls a
  finger if none is enrolled, and adds fingerprint to `/etc/pam.d/sudo` and
  `polkit-1`. `off` takes it back out and keeps your enrolled fingers for
  hyprlock; `off --forget` deletes them too. Run it bare to see the reader,
  what's enrolled, and what `sudo` and polkit do right now.
- Opt-in. It stops without changing anything on a machine with no reader. A
  failed or skipped scan always falls back to your password.
- The choice is saved as `HASHIRU_FINGERPRINT` in `hashiru.conf`, and stage 10
  puts `/etc/pam.d` back to match it on every update. Left unset, which is
  the default, Hashiru doesn't touch `/etc/pam.d` at all, so lines you added
  by hand are safe.
- `polkit-1` is rebuilt from polkit's own file on every update, so it can't
  go stale. A `polkit-1` Hashiru didn't write is left alone with a warning.
- `doctor` reports when the PAM files don't match the setting, and when
  nothing is enrolled.
- The lock screen shows a fingerprint prompt under the password box.

## Also

- The ISO release build's verify step no longer fails on CI containers that
  lack `cmp`.

## Upgrading

`hashiru update`. Nothing changes until you run `hashiru fingerprint on`.
If you already added fingerprint to `/etc/pam.d` by hand, `on` takes over
those files rather than duplicating the lines.
