# v1.7.0 — CI

The first Hashiru ISO not built on a laptop.

Tagging now builds the ISO in CI, verifies it, and publishes it with the ISO
attached. That also removes a real hazard: `build.sh` bakes the commit being
built into the image, and the installed system `git reset --hard`s to it — so a
locally-built ISO tagged afterwards would install code the tag didn't contain.
CI checks out the tag, so the pin is correct by construction.

`iso/verify.sh` is new and runs on every build. It reads the image rather than
booting it — size against GitHub's 2 GiB asset limit, the commit pin inside the
squashfs, an unsubstituted `__HASHIRU_REF__`, and `stage0.sh`'s mode. Useful
locally too, after a manual build:

```bash
./iso/verify.sh
```

A full install test still needs KVM and a display, so `iso/test-qemu.sh` stays a
local step.

## Stages

`install.sh` now checks the network only when a selected stage needs it. Stages
opt out with `# hashiru: offline` in their header; unmarked means it needs the
network, so a new stage is covered by default. `hashiru install 45` — restowing
config, the common case — went from a possible 60-second HTTPS probe to about a
second.

Two renames, done while the number of people who would notice is one:

- Stage 40 folded into 45. It created one directory, which is not worth a
  permanent stage number.
- `99-reboot.sh` → `99-apps.sh`. It had not rebooted since the prompt moved to
  the end of `install.sh`. The prompt now keys off the last stage by position
  rather than by filename, so the next rename can't quietly disable it.

Nine stages now. `./install.sh --list` shows them.

## Upgrading

`hashiru update`. Nothing here changes an installed system's shape — the stage
rename and fold are internal, and replay just runs the new set.
