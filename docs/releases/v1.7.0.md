# v1.7.0 — CI

The first Hashiru ISO not built on a laptop.

## CI builds the ISO

- Tagging builds, verifies and publishes the ISO, with the image attached.
- That closes a real hazard: `build.sh` bakes the commit being built into the
  image and the installed system `git reset --hard`s to it, so an ISO built
  locally and tagged afterwards installs code the tag doesn't contain. CI checks
  out the tag, so the pin is right by construction.
- `iso/verify.sh` is new and runs on every build, reading the image rather than
  booting it: size against GitHub's 2 GiB asset cap, the commit pin inside the
  squashfs, an unsubstituted `__HASHIRU_REF__`, `stage0.sh`'s mode.
- A full install test still needs KVM and a display, so `iso/test-qemu.sh` stays
  a local step.

## Stages

- `install.sh` probes the network only when a selected stage needs it. Stages opt
  out with `# hashiru: offline`; unmarked means it needs the network, so a new
  stage is covered by default. `hashiru install 45` went from a possible
  60-second probe to about a second.
- Stage 40 folded into 45 — it created one directory, which is not worth a
  permanent stage number.
- `99-reboot.sh` → `99-apps.sh`. It hadn't rebooted since the prompt moved to the
  end of `install.sh`. The prompt now keys off the last stage by position rather
  than by filename, so the next rename can't quietly disable it.
- Nine stages now; `./install.sh --list` shows them.

## Upgrading

`hashiru update`. Nothing here changes an installed system's shape — the rename
and the fold are internal, and replay just runs the new set.
